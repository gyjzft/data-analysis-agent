## 1. 项目概述

### 1.1 背景
当前数据分析工具（PandasAI、Julius AI 等）主要解决"用自然语言查数据、画图"的问题，但在**自动化 ML 建模**、**全流程规划**和**统计推断**方面存在空白。

### 1.2 产品定位
一个本地部署的数据分析 Agent，用户上传 CSV/Excel 数据并输入分析指令，Agent 自动规划分析流程，完成"描述统计 → 可视化 → 统计推断 → ML 建模 → 报告生成"全流程，图文展示结果。

### 1.3 核心差异化
> "别人只做查数和画图，我们能自动规划+统计推断+建模+出报告。"

### 1.4 目标用户
- 有一定 Python/统计基础，但想用 AI 提效的数据分析者
- 需要快速探索数据、建立初步模型的研究人员
- 学习 ML 建模，想看"一条龙"流程的学生

| F6 | 统计推断 | t检验、方差齐性检验、正态性检验、卡方检验 | P1 |

| F9 | ML 建模（回归） | 线性回归、决策树、随机森林、XGBoost | P1 |
| F10 | ML 建模（分类） | 逻辑回归、决策树、随机森林、XGBoost | P1 |

| F14 | 代码展示 | 展示 Agent 执行的 Python 代码（可查看/复制） | P2 |

### 2.2 MVP 不做的事（明确排除）
- ❌ 数据库连接
- ❌ 多用户/权限管理
- ❌ 实时协作
- ❌ 大规模数据（>100MB）处理
- ❌ 深度学习模型
- ❌ 时间序列预测

### 3.2 技术选型

| 层级 | 技术选型 | 选型理由 |
|------|---------|---------|
| LLM | OpenAI GPT-4o / 兼容 API（如 DeepSeek） | Function Calling 支持好 |
| Agent 模式 | Function Calling（不引入框架） | 轻量、可控、学习成本低，适合理解原理 |
| UI | Gradio | 快速搭建，你已接触 |
| 数据处理 | Pandas + NumPy | 你已掌握 |
| 可视化 | Matplotlib + Seaborn | 你已掌握 |
| ML | Scikit-learn + XGBoost | 你已掌握 |
| 统计推断 | Scipy.stats | t检验/卡方检验/正态性检验标准库 |
| 代码执行 | Python exec() + 超时控制 | MVP 阶段够用 |

### 3.3 Function Calling 工作原理

```
用户: "帮我分析这份数据的分布"

    ↓ (发送数据 schema + 用户指令给 LLM)

LLM 思考后返回:
  → 调用工具: describe_data
  → 调用工具: plot_histogram (column="price")
  → 调用工具: normality_test (column="price")

    ↓ (你的程序依次执行这些工具)

程序返回结果:
  → 描述统计表格
  → 直方图图片
  → Shapiro-Wilk 检验 p=0.02，不服从正态分布

    ↓ (结果再发给 LLM 生成自然语言回复)

Agent: "价格数据右偏，Shapiro-Wilk 检验 p=0.02，
        不服从正态分布，建议后续使用非参数检验
        或对数变换后再建模。[附直方图]"
```

### 4.1 主流程

```

 │                        │
 │── "帮我分析数据" ─────→│
 │                        │── 规划分析流程
 │←── 📋 展示分析计划 ────│
 │                        │── 逐步执行
 │←── 步骤1: 数据概览 ✅  │
 │←── 步骤2: 描述统计 ✅  │
 │←── 步骤3: 相关性分析 ✅│
```

### 4.2 典型用户对话示例

**场景：用户上传一份房价数据**

```
用户: [上传 house_data.csv]

Agent: ✅ 数据加载成功！1000 行 × 8 列，无缺失。
       数值列：price, area, rooms, age
       类别列：district, type

用户: 帮我分析影响房价的因素

Agent: 📋 分析计划：
       1. 描述统计 — 了解各字段分布
       2. 相关性分析 — 找出与房价强相关的因素
       3. 统计检验 — 验证组间差异显著性
       4. 建立预测模型 — 训练并对比 4 个模型
       
       开始执行... ▶

       [1/4] 描述统计 ✅
       price: 均值 520万，中位数 480万，右偏分布
       area: 均值 95㎡，标准差 32㎡
       
       [2/4] 相关性分析 ✅
       area(0.72) > rooms(0.58) > age(-0.43)
       [展示相关性热力图]
       
       [3/4] 统计检验 ✅
       不同区域房价 ANOVA 检验: F=12.3, p<0.001
       区域间房价存在显著差异
       
       [4/4] 建模 ✅
       | 模型 | R² | RMSE |
       | 线性回归 | 0.71 | 45.2 |
       | 决策树 | 0.68 | 48.1 |
       | 随机森林 | 0.78 | 38.5 |
       | XGBoost | 0.81 | 35.2 | ← 最佳
       [展示特征重要性图]
       
       💡 结论：面积是最强影响因素（贡献45%），
          XGBoost 模型效果最好，R²=0.81

用户: 我想看看不同区域的具体差异

Agent: [展示各区域房价箱线图]
       A区中位数 580万 > B区 450万 > C区 320万
       两两 t 检验均 p<0.05，差异显著
```

## 5. 验收标准

### 5.1 P0 功能验收

| 功能 | 验收标准 |
|------|---------|
| 数据上传 | 上传 CSV/Excel 后，自动解析并显示"✅ 已加载 X行×Y列" |
| 数据预览 | 上传后自动展示列名、数据类型、缺失值数量 |
| 分析流程规划 | 用户说"分析数据"，Agent 展示分步骤计划后再执行 |
| 多轮对话 | 连续追问 3 轮以上，Agent 能引用之前的分析结果 |

### 5.2 P1 功能验收

| 功能 | 验收标准 |
|------|---------|
| 描述统计 | 输入"描述统计"，输出均值/标准差/分位数等 |
| 统计推断 | 输入"检验正态性"，输出检验统计量和 p 值 |
| 可视化 | 4 种图表类型全部可用，图片正确显示 |
| 数据透视 | 输入"按区域透视房价均值"，输出透视表 |
| ML 回归 | 输入"预测房价"，自动训练并返回 R²/RMSE |
| ML 分类 | 输入"分类预测"，自动训练并返回准确率 |
| 模型评估 | 建模后自动输出评估指标 + 特征重要性图 |
| 图文报告 | 输入"出报告"，输出包含图表+结论的完整报告 |

### 5.3 非功能验收

| 维度 | 标准 |
|------|------|
| 响应时间 | 单次分析 < 30 秒（不含 LLM 延迟） |
| 可移植性 | `pip install -r requirements.txt` + `python main.py` 即可运行 |
| 数据安全 | 数据不上传 LLM，仅发送数据 schema（列名+类型+样本数） |
| 错误处理 | 代码执行出错时，Agent 自动重试至少 1 次 |
| 分析过程可见 | 展示分析计划 + 每步骤进度 |

## 7. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| LLM 生成的代码有 bug | 分析结果错误 | 自动重试 + 展示代码供用户审查 |
| 数据列名含中文/特殊字符 | 代码执行失败 | 自动重命名列 + 映射回原始名称 |
| 数据量过大 | 执行超时 | MVP 限制 100MB，超出提示用户采样 |
| API Key 泄露 | 安全问题 | .env 管理 + .gitignore |
| LLM 幻觉（编造统计量） | 结果不可信 | 所有数值必须来自代码执行，LLM 只负责解读 |
